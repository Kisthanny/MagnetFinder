## 新增需求

### 需求:即开即用的桌面应用

系统必须以桌面应用形式交付，承载基于 React 的用户界面。应用必须支持构建为可双击启动的产物，使用户无需每次从源码运行即可使用。开发期间必须提供本地调试启动方式。

#### 场景:双击启动

- **当** 用户双击已构建的应用产物
- **那么** 应用必须启动并展示可用的搜索界面，无需用户手动执行命令行步骤

#### 场景:本地开发调试

- **当** 开发者在本地运行开发命令
- **那么** 系统必须启动开发模式窗口并加载 React 界面，支持改动后调试

### 需求:规避 CORS 的本地请求代理

系统必须通过应用内的本地代理层（主进程）发起对第三方源的网络请求，以规避浏览器同源策略与 CORS 限制，并统一注入 `User-Agent`、`Origin`、`Referer` 等请求头。渲染层禁止直接对第三方源发起会被 CORS 阻断的请求。

#### 场景:经代理发起源请求

- **当** 界面需要向第三方源（如 apibay.org）发起查询
- **那么** 请求必须由主进程代理层发出并注入统一请求头，再将结果返回给界面

#### 场景:安全的进程隔离

- **当** 渲染层调用搜索 / 复制等本地能力
- **那么** 必须通过受控的预加载（preload）暴露的安全接口进行，保持上下文隔离开启、禁用渲染进程的 Node 集成

### 需求:合理美观的界面布局

系统的界面必须提供合理且美观的布局，至少包含：源选择、搜索输入与筛选条件区、结果列表区、以及操作反馈（加载 / 错误 / 复制成功 / 新资源通知）区域。

#### 场景:核心区域可见

- **当** 用户打开应用主界面
- **那么** 界面必须清晰呈现源选择、搜索与筛选输入、结果列表及反馈区域

#### 场景:操作状态可感知

- **当** 系统处于加载、出错、复制成功或发现新资源等状态
- **那么** 界面必须以可见的方式向用户反馈对应状态
