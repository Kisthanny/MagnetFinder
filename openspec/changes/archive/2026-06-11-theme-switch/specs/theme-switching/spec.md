## 新增需求

### 需求:在设置中切换主题
系统必须在设置面板中提供主题选择项（与语言切换并列），且必须恰好提供三个选项：亮色、暗色、跟随系统。选择后应用外观必须即时更新，无需重启。

#### 场景:切换到亮色
- **当** 用户在设置面板将主题选为「亮色」
- **那么** 应用界面必须立即应用亮色配色方案

#### 场景:切换到暗色
- **当** 用户在设置面板将主题选为「暗色」
- **那么** 应用界面必须立即应用暗色配色方案

#### 场景:三个选项齐备
- **当** 用户打开设置面板的主题选择项
- **那么** 必须能看到「亮色」「暗色」「跟随系统」三个且仅三个选项

### 需求:跟随系统主题
当主题设为「跟随系统」时，系统必须依据操作系统当前外观解析为亮色或暗色，并在操作系统外观变化时实时更新应用外观，无需用户手动操作或重启。

#### 场景:按系统外观解析
- **当** 主题设为「跟随系统」且操作系统当前为暗色外观
- **那么** 应用必须呈现暗色配色方案

#### 场景:系统外观变化时实时跟随
- **当** 主题设为「跟随系统」且用户在操作系统中切换了亮/暗外观
- **那么** 应用外观必须随之实时更新为对应配色

### 需求:主题偏好持久化
系统必须将用户的主题偏好作为权威源持久化，重启应用后必须沿用上次选择；首次启动（无已保存偏好）时默认采用「跟随系统」。

#### 场景:重启后保留选择
- **当** 用户将主题设为「亮色」并重启应用
- **那么** 应用必须以亮色启动

#### 场景:首次启动默认跟随系统
- **当** 应用首次启动且没有已保存的主题偏好
- **那么** 主题必须默认为「跟随系统」

### 需求:亮色与暗色配色方案
系统必须提供完整的亮色与暗色两套配色方案，覆盖应用的主要界面元素（背景、文字、边框、控件、结果列表、设置面板等），保证两种主题下内容均清晰可读。

#### 场景:亮色方案可读性
- **当** 应用处于亮色主题
- **那么** 文字与背景必须具备足够对比度，所有主要界面元素均清晰可读

#### 场景:暗色方案可读性
- **当** 应用处于暗色主题
- **那么** 文字与背景必须具备足够对比度，所有主要界面元素均清晰可读
