## 为什么

当前应用的界面文案全部为硬编码中文，非中文用户无法使用，也无法切换语言。需要引入多语言（i18n）能力：通过系统菜单进入设置面板切换语言，并在首次启动时默认采用用户操作系统的语言，提升可用性与受众范围。

## 变更内容

- 新增应用系统菜单项「设置 / Settings」，点击后在界面中打开设置面板。
- 设置面板提供语言切换控件，首版初始化即内置 5 种语言：简体中文（zh-CN）、英文（en）、日语（ja）、法语（fr）、西班牙语（es），切换后界面文案即时更新。
- 首次启动时默认使用用户操作系统语言；不支持的系统语言回退到英文。
- 用户所选语言被持久化，下次启动沿用上次选择。
- 将渲染层（搜索、筛选、结果列表、轮询、状态反馈等）与主进程面向用户的文案（菜单、窗口标题等）全部抽取为可翻译资源，消除硬编码。
- 主进程菜单文案随当前语言本地化。

## 功能 (Capabilities)

### 新增功能
- `localization`: 多语言能力，涵盖系统菜单设置入口、设置面板的语言切换（首版内置简体中文 / 英文 / 日语 / 法语 / 西班牙语 5 种）、系统语言默认与回退、语言偏好持久化、主进程与渲染层 UI 文案的翻译与即时切换。

## 影响

- 新增渲染层 i18n 基础设施（语言上下文 / provider、翻译资源文件、文案 hook）。
- 新增设置面板组件与触发其打开的 IPC 通道（主进程菜单 → 渲染层）。
- 修改主进程：构建带「设置」项的应用菜单、按当前语言本地化菜单文案、读取系统语言（`app.getLocale`）、读写语言偏好持久化。
- 修改既有渲染层组件（`App.tsx`、`SearchControls.tsx`、`ResultList.tsx` 等）与共享文案（如清晰度标签）以使用翻译资源替换硬编码中文。
- 可能新增轻量依赖（i18n 库或自建轻量方案，详见 design.md）。
