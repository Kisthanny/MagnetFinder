## 需求
### 需求:单集定时轮询

系统必须支持针对指定季与集的查询开启定时轮询。轮询间隔必须可配置，默认值为 60 秒。轮询必须可由用户随时启动与停止。

#### 场景:开启轮询

- **当** 用户对一个已指定季与集的查询开启轮询
- **那么** 系统必须按配置的间隔周期性重新执行该查询

#### 场景:停止轮询

- **当** 用户停止正在进行的轮询
- **那么** 系统必须立即终止后续的定时查询，且不再产生新的轮询请求

#### 场景:可配置间隔

- **当** 用户设置一个自定义轮询间隔
- **那么** 系统必须以该间隔执行轮询；未设置时必须使用默认 60 秒

### 需求:发现新资源时通知

系统在轮询过程中必须对比相邻两次查询的结果集，按资源 `id` 或 `infoHash` 去重识别新增资源，并在发现新增资源时通知用户。

#### 场景:发现新增资源

- **当** 某次轮询返回的结果中包含上一次未出现的资源
- **那么** 系统必须将其标记为新增并通知用户

#### 场景:无新增资源不打扰

- **当** 某次轮询返回的结果与上一次相比没有新增资源
- **那么** 系统禁止发出新资源通知
