# localization 规范

## 目的
待定 - 由归档变更 multi-language-support 创建。归档后请更新目的。
## 需求
### 需求:系统菜单中的设置入口

系统必须在应用的原生系统菜单中提供一个「设置」入口。用户点击该入口时，系统必须打开设置面板。该菜单项的文案必须随当前语言本地化。

#### 场景:通过菜单打开设置面板

- **当** 用户点击系统菜单中的「设置」入口
- **那么** 系统必须打开包含语言切换控件的设置面板

#### 场景:菜单文案本地化

- **当** 当前语言为某一受支持语言
- **那么** 系统菜单中「设置」入口的文案必须以该语言显示

### 需求:在设置面板中切换语言

设置面板必须提供语言切换控件，列出所有受支持的语言（以各语言的原生名称展示）。用户选择某一语言后，系统必须立即将界面文案切换为该语言，无需重启应用。

#### 场景:切换语言即时生效

- **当** 用户在设置面板中选择一个与当前不同的受支持语言
- **那么** 系统必须立即将界面所有已翻译文案更新为所选语言

#### 场景:展示受支持语言列表

- **当** 用户打开设置面板的语言切换控件
- **那么** 控件必须列出全部受支持语言，并以各自的原生名称展示

### 需求:默认使用系统语言并回退

系统在首次启动（无已保存语言偏好）时，必须采用用户操作系统的语言作为默认界面语言。当操作系统语言不在受支持列表中时，系统必须回退到英文。

#### 场景:系统语言受支持

- **当** 应用首次启动且操作系统语言属于受支持语言
- **那么** 系统必须以该系统语言展示界面

#### 场景:系统语言不受支持时回退

- **当** 应用首次启动且操作系统语言不属于受支持语言
- **那么** 系统必须以英文展示界面

### 需求:语言偏好持久化

用户选择的语言必须被持久化保存。应用再次启动时，必须沿用上次保存的语言偏好，而非重新依据系统语言判定。

#### 场景:重启后沿用所选语言

- **当** 用户曾切换并保存某一语言，之后重新启动应用
- **那么** 系统必须以上次保存的语言展示界面

### 需求:界面与菜单文案的翻译覆盖

系统面向用户的文案（包括渲染层界面与主进程的菜单、窗口标题等）必须通过翻译资源提供，禁止保留硬编码的单一语言文案。在受支持语言下，界面禁止出现未翻译而回退为其它语言的可见文案。

#### 场景:界面文案随语言一致呈现

- **当** 当前语言为某一受支持语言
- **那么** 渲染层界面与原生菜单中的应用自有文案必须全部以该语言呈现

#### 场景:动态资源数据不受影响

- **当** 搜索结果包含第三方源返回的资源标题等动态数据
- **那么** 系统不要求翻译该动态数据，但其周边的应用 UI 文案仍必须以当前语言呈现
